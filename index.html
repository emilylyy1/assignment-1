Little Keys — A Musical Playground

Brief synopsis

Little Keys is a browser-based musical toy designed for toddlers to explore sound through large, colourful piano keys. Each press creates a note and a playful visual response, encouraging curiosity and experimentation without requiring musical knowledge or reading skills.

Chosen design scenario

Scenario: A musical toy designed for toddlers to explore music in a fun and engaging way.

Prompt: Design a way for toddlers to play music and feel excited about their creations.

The scenario frames success around excitement, curiosity and cause-and-effect rather than technical musical skill. The interface therefore prioritises simple actions, clear feedback and an inviting visual style.

How the final project responds

Little Keys presents a simple keyboard with large, colourful keys. Each key produces a distinct tone and animates when pressed. Children can explore using a mouse, touchscreen or mapped computer keyboard, without needing to read instructions or navigate complicated controls.

Project documentation

Core interactive features

1. Play a note

Each key is an HTML button associated with a musical pitch. Clicking or tapping a key calls the play function, which generates a note and provides immediate visual feedback.

2. Computer keyboard input

The A, S, D, F, G, H, J and K keys trigger the corresponding notes. This provides an additional way to play while retaining the simple, single-action interaction.

3. Visual feedback

When a key is played, a temporary animation changes its position and shadow. A status message also communicates which note was played, so the interaction has both audio and visual feedback.

4. Extended technique — browser-based sound synthesis

The extended technique is the use of the Web Audio API to generate sound directly in the browser rather than loading prerecorded sound files. An oscillator generates the tone, its frequency determines the pitch, and a gain node controls volume and fades the sound smoothly. Audio starts after the user interacts with the page to respect browser autoplay restrictions.

5. Sound toggle and surprise button

The sound toggle allows the user to silence the instrument while continuing to interact with the keys. The surprise button chooses and plays a random note, encouraging playful discovery.

Responsive and adaptive design system

Layout and breakpoints

  • Medium — below 840px: the keys rearrange into two rows of four, with spacing adjusted for smaller screens.
  • Expanded — 840px to 1199px: the keyboard uses a fluid layout and remains centred.
  • Large — 1200px to 1600px: the instrument can use more available width while retaining clear, large keys.
  • Extra-large — above 1600px: the instrument remains centred within a maximum width so it does not stretch excessively.

These breakpoint behaviours are implemented with CSS media queries. Test the actual published page at the required widths before submission and adjust the description if the implementation changes.

Typography, colour and information design

Rounded Nunito typography and a pastel palette support a friendly, toy-like atmosphere. Each key uses its own colour and symbol to make choices easy to distinguish. The interface keeps the keyboard and essential controls together on one screen, avoiding extra menus and unnecessary information.

Accessibility and feedback

The keys are semantic buttons with accessible labels and visible keyboard-focus styles. Large touch targets support imprecise tapping, symbols and labels mean colour is not the only cue, and reduced-motion preferences are considered. The live status message provides feedback about the last note played. Sound is not triggered automatically on page load.
